# Dead-Fest v2.0.7.2

**Build 12.** Two downloads, a proper splash screen, screen-reader support, and releases that stop
depending on one laptop having the right keystore.

Updating installs straight over what you already have. Nothing is reset, nobody is logged out, and
your coins, level and history are untouched.

## Two builds, your choice

This release is published twice. Same version, same features, same signing key — the only difference
is how the file was packaged, so either one installs over the other whenever you change your mind.

Both are version 2.0.7.2, build 12, `minSdk 24`, package `com.deadfest`, signed with certificate
`SHA-256 876d1bfd47566e4c3530397ececebc562795059c7d984e65a4d8f85caf260bcc` — the same one every

> One honest note about the full build: it is a *debug* build, so it carries `android:debuggable=true`.
> That does not affect normal use, but it does mean the app's private data can be read over a USB
> connection by anyone who has your unlocked phone and has turned on USB debugging. If that matters to
> you, take the R8 build.

**Settings → Update** now shows both and lets you pick which one the app should fetch. The app starts
by offering you the same kind of build you are already running, so an update never quietly swaps you
onto the other one.

If only one of the two has been uploaded, everyone is served that one rather than being told there is
nothing to install.

## New splash screen

Cold start now shows the Dead-Fest skull on ink instead of a blank window — and it looks the same on
every Android version from 7.0 up, not just on Android 12+ where the system invents one from the
launcher icon.

It also waits for your saved session to come back before handing over, so a returning survivor can no
longer glimpse an empty dashboard or the login screen for a frame. That wait is capped, so a broken
session can never strand you behind a logo.

## Screen-reader support

TalkBack and Switch Access work properly across the app now:

- **The countdown reads as a time, not as numbers.** It used to be eight separate stops —
  "zero zero", "one two", "DAYS" — which had to be reassembled in your head while the digits moved.
  It is now one stop, spoken as "Starts in 2 days 5 hours 30 minutes", and deliberately rounded to the
  minute so it holds still. The tiles still tick every second for everyone else.
- Section titles are headings, so you can jump between sections instead of reading a screen as one
  wall of text.
- Progress bars report their real value instead of being invisible.
- Label/value rows read as one fact — "Coins, 1,240" — rather than two unrelated numbers.
- Selected options announce that they are selected, instead of relying on a colour change.
- Small controls got proper touch targets, and the back button in every header is now 48dp.
- Icons that only repeat the text next to them are no longer read out twice.

## Releases are no longer hand-made and unsigned

`app/build.gradle.kts` now signs `assembleRelease` and `assembleDebug` from a keystore read out of
`local.properties` (gitignored) or the environment. A GitHub Actions workflow builds, runs the tests,
signs both variants, **verifies both certificates against the expected fingerprint**, and publishes
the release on a tag. See [docs/SIGNING.md](../docs/SIGNING.md).

The signature is deliberately the same one every earlier build carried. A different key would make
Android refuse the update and force everyone to uninstall first — losing their saved session — so the
workflow treats a certificate mismatch as a failed release.

## Not in this release

- **The baseline profile is not measured yet.** The runtime half (`profileinstaller`) is in, but the
  profile itself has to be generated by running a macrobenchmark on a real device, and no device was
  available. Writing one by hand would be inventing measurements. See
  [docs/BASELINE_PROFILE.md](../docs/BASELINE_PROFILE.md) for the one command that generates it.
